### แต่งตัวอวาตาร์ — ห้องแต่งตัว (flag `NEXT_PUBLIC_AVATAR_CUSTOMIZE`)

- Patch note "อัปเดตใหม่ — แต่งตัวอวาตาร์ในแบบของคุณ" publish ใน `/admin/patch-notes` ตอน 06:18 UTC

**หมายเหตุ**

1. **app p95** — histogram ของ Traefik มี bucket แค่ 0.1 / 0.3 / 1.2 / 5 s ค่า ~0.95 s จึงเป็นค่าประมาณในช่วง 0.3–1.2 s ไม่ใช่ค่าที่วัดตรง ๆ · ที่เปลี่ยนจริงคือ request 0.3–1.2 s ขึ้นจาก 0.006 → 2.34 req/s · น่าจะเป็นการโหลด sprite sheet ที่ bake ใหม่ผ่าน proxy `/api/img` (hash ใหม่ = URL ใหม่ = cache miss) — **ยังยืนยันราย path ไม่ได้** เพราะ Traefik ไม่มี access log
2. **ต้นเหตุโหลดช่วงพีค** — ห้องแต่งตัว autosave ทุกการเปลี่ยน (debounce 600 ms) · 06:17–06:30 มี PUT outfit 629 ครั้งจาก 17 คน · ทุกครั้ง bake + อัป GCS ~300 ms แล้ว client โหลดรูปใหม่ผ่าน app
3. **error ที่เจอ**
   - api: `500` ×1 บน PUT outfit — `context canceled` (request ถูกยกเลิก) เพราะ client ยกเลิก PUT ก่อนหน้าเอง (1 ใน 629) แต่ log เป็น ERROR
   - app: `500` ~33 ครั้ง 06:28–06:29 — `Error: Failed to find Server Action` (หา Server Action ไม่เจอ) จากแท็บที่เปิดโค้ดเก่าค้างไว้ · 7 วันก่อนหน้ามี 359 ครั้ง = อาการปกติหลัง deploy ทุกรอบ หายเมื่อ refresh
   - app: `502` ×2 (06:33) และ `503` ×4 (06:46) ช่วงพีค · pod ไม่ restart และ ready ตลอด
   - app: log ใหม่ `Error: ENVIRONMENT_FALLBACK` (next-intl ไม่ได้ตั้ง timeZone) ×2 — ก่อนหน้า 72 ชม. มี 0
4. **ws** ดีขึ้นจาก `VO_TICK_*` — งานต่อ tick ลดลงมาก และ tick ไม่หลุดเลย (sim 50 Hz)

**ยังไม่ได้วัด** — Sentry (ไม่มี login) · `force_sync` (ไม่มี log ฝั่ง server) · Lite / Android low-end (เป็น client-side ล้วน) · app traffic ราย path (ไม่มี access log) · Pyroscope (ไม่มี datasource) · After window ของ ws/DB (วัดเฉพาะรอบแรก)
