## zyra-api

### ทนโหลดขึ้น (#176) — จาก load test บน prod clone 2026-10-19

ที่มา: `plan/LoadTest/results/2026-10-19.md` (ยังไม่ได้ push ขึ้น zyra-doc)

- **health probe ไม่แย่ง connection กับ request จริงแล้ว** — เดิม `/api/health` ping DB ผ่าน pool เดียวกับ request ตอนโหลดหนัก ping ต่อคิวจน readiness probe (1 วิ) timeout → pod เดียวหลุดจาก Service → ทุก request ได้ 503 ตอนนี้มี loop เบื้องหลัง ping ผ่าน connection ของตัวเอง handler แค่รายงานผลล่าสุด
- **DB pool 4 → สูงสุด 20** — pgxpool เดิมใช้ค่า default `max(4, NumCPU)` = 4 ตอนนี้ตั้งด้วย `DB_MAX_CONNS` (default 20) · `MinConns` 2 · ถ้าใส่ `pool_max_conns` ใน `DATABASE_URL` ค่านั้นชนะ
- **`GET /api/maintenance` ไม่ยิง DB ทุกครั้ง** — เดิมคิดเป็น ~50% ของ query ตอนปกติ ตอนนี้ cache 3 วิ และ refresh ทันทีเมื่อเปิด/ปิด maintenance
- **ความปลอดภัย: `GET /api/user/workspaces/:id/members` ต้องเป็นสมาชิกหรือ owner** — เดิมคืนอีเมลของสมาชิกทุกคนให้ใครก็ได้ที่ login อยู่ ฝั่ง app ที่เรียก endpoint นี้ (`workspace-enter`, `workspace-loading`) มี `.catch()` อยู่แล้ว ถ้าโดน 403 แค่ไม่ prefill ชื่อตัวละคร ไม่พัง
