### 2. ป้ายสภาพอากาศโฉมใหม่ (Figma `6182:724026`)

เปลี่ยนจาก lucide เป็น artwork จริงของดีไซน์ครบ 11 สภาพอากาศ · tile ซ้ายเปลี่ยนสีตามเวลา (เช้า/เย็น/กลางคืน) และเป็นโทนเทาเมื่อฝน/หมอก/หิมะ (`6182:724014`) · ปุ่ม `:::` อยู่ในแถบและเป็นจุดเดียวที่ลากย้ายได้ กดที่อื่น = เปิด panel

**บทเรียนเรื่อง asset:** ไฟล์ที่ดีไซน์ export มาไม่ได้พก "กรอบ" ที่เขาจัดไว้มาด้วย — ทุก variant ถูกวาดในกรอบ 40×32 เดียวกัน แต่ export ออกมาพร้อม blur ที่ล้นกรอบ canvas เลยกว้าง 40×32 ถึง 72×112 ⇒ ถ้าจัดขนาดจากขอบไฟล์จะได้คนละขนาดทุกอัน ต้องไปดึงกรอบจาก component set มา re-frame เอง (รายละเอียดใน [[progress]] รอบ 25)

### 3. ชื่อสถานที่เป็นภาษาเดียวทั้งระบบ

**`language=en` อย่างเดียวไม่พอ** — Google ตอบ `หนองแขม` เท่ากันทั้งที่ใส่และไม่ใส่ พารามิเตอร์นี้เลือกได้แค่จากชื่อที่ Google มี ต้องถามเป็น "พื้นที่" (`result_type=sublocality|locality|administrative_area_level_2`) ถึงจะได้ชื่อโรมัน · จุดที่ไม่มีพื้นที่ประเภทนี้ตอบ ZERO_RESULTS ⇒ fallback ไปถามแบบเดิม

`BackfillPlaceLabels` ไล่แก้ของเก่าครั้งละ 20 แถวบน poller tick แล้ว stamp `env_place_lang` ทิ้งไว้เพื่อไม่ให้วนซ้ำ

## แก้ไข

### 4. 🔴 poller lock ไม่มี prefix — dev/uat/prod แย่ง lock เดียวกัน

dev, uat และ prod ใช้ Memorystore ตัวเดียวกัน แต่ lock เป็น key เปล่า `env:poller:alerts` ⇒ **ล็อกเดียวสำหรับสาม environment** ใครคว้าได้ก่อนถือ 4m30s จากทุก 5 นาที · environment ที่แพ้ถูกปิดเงียบทั้ง alert poll, weather refresh และ backfill

พบเพราะ backfill บน dev ไม่ขยับสักแถวหลัง deploy ทั้งที่โค้ดถูก (เดาผิดไปหนึ่งรอบว่าเป็นเรื่อง context timeout) แก้โดย scope lock ด้วยชื่อ database — env ที่แชร์ Redis กันไม่เคยแชร์ DB กัน

**กระทบ prod โดยตรง:** ที่ผ่านมา prod อาจไม่ได้ poll ประกาศเตือนภัยเป็นช่วง ๆ เพราะ dev/uat แย่ง lock ไป

### 5. rollout ของ prod app ค้างเพราะ CPU node เต็ม (zyra-infra #43)

v1.5.4 ฝั่ง app **ค้าง Pending 15 นาที**: `0/1 nodes are available: 1 Insufficient cpu` — node จอง CPU ไว้ 3665m/4000m (91%) และ `maxSurge 25%` (= 1 pod ที่ 2 replica) ขอเพิ่มอีก 500m ที่ไม่มี

แก้เป็น `maxSurge: 0 / maxUnavailable: 1` เฉพาะ prod app (opt-in ผ่าน `rollout:` ใน chart) ⇒ เปลี่ยนทีละ pod ในที่เดิม ไม่ต้องขอ CPU เพิ่ม · แลกกับช่วง deploy ที่เหลือ 1 replica ~40 วิ

pod เก่าขึ้นเมื่อ 18 ก.ย. ซึ่งหลัง secret v3 แล้ว ⇒ อ่านค่าว่างเหมือนกัน ไม่ใช่ของใหม่ · ผลตาม [[07-monitor]]: OTP ไม่ถูกส่งอีเมลแต่ถูก return กลับใน response ⇒ สมัครสมาชิก/รีเซ็ตรหัสผ่านใช้ไม่ได้ตามปกติ และ OTP หลุดออกทาง API

### node เดียวจอง CPU 91%

e2-standard-4 ตัวเดียว requests 3665m/4000m · incident 3 รอบล่าสุด ([[prod-app-crashloop-2026-09-10]] · [[node-saturation-2026-09-18]] · [[node-cpu-burst-argocd-2026-09-22]]) สาวกลับมาที่จุดนี้หมด · #43 แค่ปลดล็อก rollout ไม่ได้เพิ่ม headroom

### ArgoCD ไม่มี user นอกจาก admin และไม่มี ingress

`argocd-cm` มีแค่ `admin.enabled` ไม่มี `accounts.*` และไม่มี oidc/dex config · `argocd-server` เป็น ClusterIP ไม่มี ingress ⇒ เข้าได้ทาง `kubectl port-forward` ด้วย user `admin` เท่านั้น · `url` ยังเป็น placeholder `https://argocd.example.com`
