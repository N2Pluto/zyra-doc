คำตอบสั้น

Background WebSocket: ระหว่างประชุมทำได้ทั้ง iOS (audio background mode) และ Android (foreground service) · นอกประชุม iOS ทำไม่ได้และไม่ควรพยายาม แก้ด้วย grace period ฝั่ง zyra-ws แทน

Background audio: ทำได้บน iOS ≥ 17.5 ด้วย config ล้วน (Info.plist + WKWebView flag + media ต้องเป็น UDP) · Android ต้องมี foreground service ซึ่งเป็นงาน native ชิ้นเดียวใน Tier 1

Reconnect: โค้ดมีครบแล้วราว 90% ต้องเพิ่มแค่ bridge lifecycle ของ Capacitor เข้า handler เดิม และปิดช่องว่างฝั่ง server (grace + restore sitting)

1. ต้อง native จริง vs ทำใน WebView ได้

Tier 1 ทั้งหมดเป็น config + plugin official ไม่ต้องเขียน Swift/Kotlin เอง ยกเว้น foreground service บน Android และหน้า offline ของ shell ซึ่งเล็ก งาน native ใหญ่จริงมีแค่ screen share กับ PiP (Tier 3)

2.2 สิ่งที่เกิดกับ zyra-ws เมื่อแอปถูก suspend (จากโค้ดจริง)

client: heartbeat ทุก 20s (vo-session-store.ts:432) หยุด · Worker ticker 100ms (scene.ts:3100) หยุด
server: pingPeriod 45s / pongWait 60s (client.go:17-20)
  ├─ OS ปิด socket ทันที → ReadPump ออก → room.unregister (client.go:370)
  └─ OS ค้าง socket → pong ไม่ตอบ → ปิดหลัง 60s → unregister
unregister (room.go:506-626) — ไม่มี grace period:
  releaseSeat → ออกจาก meeting chat / audio room / screen share → MediaRoomID = ""
  → SetLastPosition (tile+direction ไม่เก็บ sitting) → DeletePresence → broadcast MsgLeft ทันที
presence TTL 35s (redis.go:17) หมดอายุก่อนหน้านั้นอยู่แล้ว
รอดข้ามการหลุด: follow 30s · chat circle 5s · spotlight 2 นาที

ผล: ผู้ใช้กด Home 1 นาที คนอื่นเห็นว่าออกจาก office กลับมาอีกครั้งคือ join ใหม่ ยืนอยู่ tile เดิมแต่ไม่นั่งแล้ว ต้อง mediaRoomEnter ใหม่ (client ทำให้อยู่แล้ว)

3. Background audio + reconnect ทำได้ไหม

3.1 Background audio บน iOS

iOSWebRTC ใน WKWebView ตอน backgroundแหล่ง
14.7 – 17.4ได้ยินคนอื่น แต่ mic ตัวเองถูก mute สั่งกลับไม่ได้Apple forum 689182
≥ 17.5.1ใส่ audio ใน UIBackgroundModes แล้ว ทำงานเหมือน Safari ทั้งฟังและพูดApple forum 689182 (Aug 2024)
18เสียง WebRTC ไม่ออกถ้าไม่ตั้ง mediaTypesRequiringUserActionForPlayback = []Apple forum 764453
26 (Element X = LiveKit web ใน WKWebView)ยังมีรายงานเสียงหายสองทางเมื่อ media ตกไป TCP iOS ตัด TCP background แรงกว่าelement-call #4184 (ยังเปิด)

ต้องทำ (config ทั้งหมด): Info.plist UIBackgroundModes = [audio] · WKWebView allowsInlineMediaPlayback + mediaTypesRequiringUserActionForPlayback = [] · ฝั่งเว็บตั้ง navigator.audioSession.type = "play-and-record" ตอนเข้าประชุม (iOS ≥ 17, Web API) · zyra-sfu ตรวจว่า UDP ไม่ชน TURN และ client ไม่ตก TCP-only · ตั้ง minimum iOS 17.5

Android: foreground service ตอนอยู่ในประชุม (Android 14+ บังคับ foregroundServiceType microphone) ไม่งั้น OS ตัด mic เมื่อไป background นี่คืองาน native ชิ้นเดียวใน Tier 1

CallKit: ไม่ทำ WKWebView กับ CallKit ถือ AVAudioSession คนละ thread แย่งกัน (Apple forum 685268) ถ้าต้องการสายเข้าจริงต้องย้ายเสียงไป native LiveKit SDK ซึ่งเป็น Plan B
