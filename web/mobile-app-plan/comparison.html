Capacitor vs Expo vs Flutter vs ตัวเลือกอื่น

เปรียบเทียบจากข้อเท็จจริงในโค้ด zyra-app จริง (PixiJS engine ~27k บรรทัด, HUD ~49k บรรทัด, livekit-client, raw WebSocket, cookie auth, Next.js standalone) ไม่ใช่การเทียบ framework ลอย ๆ

Capacitor + native feature จริง เพราะเป็นทางเดียวที่ขึ้น store ทั้งสองพร้อม Full VO ได้โดยไม่ rewrite โค้ด ~76k บรรทัด · Expo เป็น Plan B เมื่อชน trigger (FPS < 20 หลัง tuning หรือ Apple reject 4.2 สองรอบ) · Flutter ไม่เลือก เพราะ rewrite ทั้งหมดเป็น Dart และแชร์กับ zyra-app ไม่ได้เลย

Capacitor (Ionic)

แนะนำ
WebView shell ครอบ zyra-app ที่มีอยู่ โหลดจาก URL จริงของแต่ละ env

ข้อดี

  • ใช้โค้ดเดิม 100% ทั้ง engine, HUD, livekit, ws, auth deploy เว็บ = deploy mobile
  • ขึ้น store ทั้งสองจาก project เดียว plugin official ครบ: push, haptics, status bar, splash, keep-awake, deep link
  • WebRTC + WebGL รันใน WKWebView / Android WebView ได้ (iOS 14.3+)
  • Google/Apple sign-in ผ่าน native plugin แล้วยิง id_token เข้า endpoint เดิม ไม่ต้องแก้ backend
  • ทีม React/TS เดิมทำได้ทันที ไม่มี second codebase
  • โหมด remote URL แก้บั๊กเว็บแล้ว mobile ได้ทันที ไม่ต้อง submit store ใหม่
  • reconnect / visibility handling ที่มีอยู่แล้วใน workspace-ws.ts, use-meeting-media.ts, hero, engine ใช้ต่อได้ ~90%

ข้อเสีย / ความเสี่ยง

  • Apple Guideline 4.2: แอปที่เป็นแค่เว็บใน WebView โดนปฏิเสธได้ ต้องมี native feature จริง
  • Performance ต่ำกว่า native โดยเฉพาะ Android เครื่องล่าง ต้อง profile บนเครื่องจริง
  • Screen share บนมือถือทำไม่ได้ใน WebView ต้องเขียน native plugin เอง (งานใหญ่)
  • iOS background: WebView ถูก suspend นอกประชุม WebSocket ค้างไม่ได้ ต้องแก้ด้วย grace period ฝั่ง zyra-ws
  • Background audio ต้อง iOS ≥ 17.5 (ต่ำกว่านั้น mic mute ตอน background) · CallKit ใช้กับ WebRTC ใน WKWebView ไม่ได้
  • Remote URL: server ล่ม = app ล่ม และต้อง whitelist navigation
  • Native feel ต่ำสุดในสามตัว transition / keyboard ต้องปรับเอง

Expo / React Native

Plan B
แอป native ด้วย React เขียน UI และ engine ใหม่ แชร์ได้เฉพาะ lib ที่ไม่แตะ DOM

ข้อดี

  • Native UI, performance ดีกว่า WebView ทีม React ใช้ tanstack-query / zustand เดิมได้
  • @livekit/react-native SDK official รองรับ background audio ดีกว่า WebView มาก
  • EAS Build / Submit / Update ครบ build ทั้งสอง platform บน cloud และ OTA update JS ได้
  • แชร์ types, ws client, api client ได้ถ้า refactor ให้ไม่แตะ DOM
  • ไม่มีปัญหา 4.2 และไม่มีปัญหา WebView suspend

ข้อเสีย / ความเสี่ยง

  • ต้อง rewrite game engine 27k บรรทัด PixiJS v8 ไม่มี RN renderer ต้องใช้ react-native-skia หรือ expo-gl + engine ใหม่
  • ต้อง rewrite HUD 49k บรรทัด (Tailwind → StyleSheet / NativeWind, radix → RN component)
  • Two codebases ถาวร feature ใหม่ทำ 2 รอบ บั๊ก VO desync ต้องไล่ 2 ที่
  • Auth ต้องเปลี่ยนจาก cookie เป็น bearer + SecureStore
  • เวลาถึง store นานที่สุด (หลักเดือน)

Flutter

ไม่แนะนำ
Rewrite ทั้งหมดเป็น Dart ใช้ Flame เป็น game engine

ข้อดี

  • Performance และความสม่ำเสมอ iOS/Android ดีที่สุด (Impeller render เอง)
  • livekit_client SDK official, Flame เหมาะกับ 2D tile map
  • Tooling ครบ hot reload ดี

ข้อเสีย / ความเสี่ยง

  • Rewrite ทั้งหมด ~76k บรรทัด TS → Dart แชร์กับ zyra-app ไม่ได้แม้แต่ types
  • ทีมต้องรักษา 2 ภาษา 2 stack sprite/asset pipeline ทำใหม่
  • ไม่มี OTA อย่างเป็นทางการ (Shorebird เป็น third-party)
  • เวลาถึง store นานเท่ากับหรือมากกว่า RN
