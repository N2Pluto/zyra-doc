### เจอเพิ่ม — ยังไม่มีในเอกสาร

> ฉบับส่ง dev (ระบุไฟล์/บรรทัด · สิ่งที่ต้องแก้ · วิธี verify · ตารางไว้ assign) + จุดที่ไม่ตรง API contract อีก 8 ข้อ อยู่ที่ **[code-findings-2026-08-31.md](code-findings-2026-08-31.md)** — 8 ข้อล่างนี้คือสรุปย่อ (= F1, F2, F3, F12, F15, bootstrap DDL, F13, F14)

1. **Progress bar ยังเป็นสเกล 17 slots** — `PET_UPLOAD_PROGRESS_WIDTHS` มี 18 ค่า (step ละ 5.88% = 100/17) แต่ total เป็น 20 → บาร์เต็ม 100% ตอนอัปโหลดครบ 17/20 (`pet-detail-panel.tsx:33-52` + fallback `?? "w-full"` บรรทัด 97) เป็นเศษของ spec 17 slots ที่ยังค้างในโค้ด กระทบทั้งหน้า create/edit และ `PetSelectedView`
2. **Preview modal ใช้ metadata ชุดที่ 3** — hardcode 6 เฟรม × 4 rows @ 8fps และ `void animationMeta` ทิ้งค่าจริงจาก DB ทั้งชุด แถมไม่ใช้ prop `frameCount/frameRate` (50/24) ที่ส่งเข้าไป (`pet-preview-modal.tsx:166-180`) → ตอนนี้มี 3 สัญญาที่ไม่ตรงกัน: DB (ค่าจริง) · upload (50/24/4) · preview (6/4/8) เอกสารพูดถึงแค่ตัว upload
3. **ข้อจำกัดฝั่ง API ขัดกับ metadata ที่ล็อกไว้ — จะทำให้ UAT ไฟล์จริงไม่ผ่าน** — API จำกัดชีท ≤1000×1000 px และ ≤1 MB (`pet_service.go:24`, `:512-523`) ขณะที่ frame_count ถูกล็อก 50 → เฟรมกว้างได้ไม่เกิน 20px (เคส "valid" ใน unit test เองคือ 1000×400 → 20×100) ชีท 50 เฟรมที่เฟรมขนาดปกติ (64px = 3200px) จะโดน `INVALID_DIMENSIONS` ทันที
4. **ขอบเขต Go test แคบกว่าที่เขียนไว้** — มีจริง 4 test func ฝั่ง pet (`validatePetAnimationInput`, `validatePetSpriteDimensions`, `isGIFName`, `stageReadiness`) + XP validation/error-mapping ทั้งหมดเป็น pure function **ไม่มี service test ที่ mock DB และไม่มี `pet_handler_test.go`** → ยังไม่ถึง target ≥80% ของ `internal/service/*` ตาม `.claude/rules/04-test.md`
5. **Feature flag ปิดแค่เมนู** — `isPetManagementEnabled()` ถูกใช้ที่ sidebar ที่เดียว; route `/admin/pet-management` และ `/admin/pet-management/xp-configuration` ยังเปิดตรงผ่าน URL (มีแค่ `AdminGuard`) และ `/api/admin/pets*` ไม่มี flag เลย — ถ้อยคำในเอกสาร ("เมนูถูกควบคุมด้วย flag") ถูกตามตัวอักษร แต่ถ้าเจตนาคือ "ยังไม่เปิดฟีเจอร์" ตอนนี้ยังปิดไม่จริง
6. **ตาราง Pet ไม่ต้องรัน migration มือ** — `tb_pet_type` / `tb_pet_animation` / `tb_pet_xp_config` + seed config v1 อยู่ใน bootstrap DDL ของ `zyra-api/internal/database/postgres.go:782-868` แล้ว → ถูกสร้างตอน service start เอง; และ `migrations/84_pet_animation_idle_slot.sql` เป็น no-op เทียบกับ 83 ในรีโปปัจจุบัน (83 มี `'Idle'` อยู่ในชุด CHECK แล้ว — 84 มีผลเฉพาะ DB ที่รัน 83 เวอร์ชันเก่าไปแล้ว)
7. **XP panel ผิดกฎ Tailwind-only** — import `@/components/ui/dialog` และ `@/components/ui/dropdown-menu` ซึ่ง `.claude/rules/08-shadcn-ui.md` ห้าม (ทั้งรีโปมี 24 ไฟล์ใน `views/` ที่ทำแบบเดียวกัน — ไม่ใช่ปัญหาเฉพาะ Pet แต่ถ้าจะ enforce ต้องนับรวม)
8. **เล็กน้อย** — ช่อง search ใน Pet Library ยิง `listPets` ทุกครั้งที่พิมพ์ ไม่มี debounce (`pet-library-panel.tsx:58-67`)

## จุดที่ต้องตัดสินใจหรือแก้ให้ตรง spec

### Required animation slots

โค้ดต้องการ 20 slots: Egg 2 + Baby/Adult/Evolved stage ละ 6 โดยเพิ่ม Idle

ยืนยันกับ PM/Design ว่าจะเก็บ Idle หรือยึด spec เดิม 17 slots; ปรับ FE/BE/เอกสารให้ใช้คำตอบเดียวกัน

### Animation metadata

หน้าเว็บส่ง fixed 50 frames, 24 fps, 4 direction rows และ select ถูก disabled

เปิดให้ตั้งค่าต่อ animation ตาม spec หรือปรับ spec ให้ยอมรับค่า fixed อย่างเป็นทางการ

### XP configuration vs XP earning

การตั้งค่าและ history พร้อม แต่ยังไม่มี consumer ที่อ่าน config เพื่อให้ XP จริง

ทำ XP engine หลังมี Room Pet ledger เพื่อหลีกเลี่ยง config ที่บันทึกได้แต่ไม่ส่งผลในระบบ

### Deployment readiness

เมนูถูก feature-flag แต่ API/Admin code อยู่ใน branch แล้ว; CI Go เคย fail จาก router wiring และแก้ใน working tree แล้ว

commit การแก้ CI แยกตาม workflow แล้วรัน test/build ก่อนเปิด flag

> เพิ่มจากรอบตรวจโค้ด 2026-08-31: ยังมีอีก 3 เรื่องที่ต้องตัดสินใจ/แก้ — สเกล progress bar ที่ยังเป็น 17 slots, preview modal ที่ hardcode 6×4@8fps, และเพดาน 1000px ที่ขัดกับ frame 50 (บล็อก UAT) ดู [§เจอเพิ่ม](#เจอเพิ่ม--ยังไม่มีในเอกสาร) #1–#3

## เกณฑ์ก่อนเปิด Feature Flag

เปิด `NEXT_PUBLIC_PET` สำหรับผู้ใช้งานเมื่อทำครบ: Room Pet placement และการย้าย/ลบผ่าน Map Editor, realtime ข้ามผู้ใช้, XP ledger ที่กันการจ่ายซ้ำได้, render ตาม stage/mood, integration/UAT บน dev และ CI ผ่านทั้ง API กับ app

ระหว่างนี้สามารถใช้ Pet Management เพื่อเตรียม pet type, sprites และ XP config ในระดับ Admin ได้ แต่ไม่ควรสื่อว่า pet ทำงานใน Virtual Office แล้ว
