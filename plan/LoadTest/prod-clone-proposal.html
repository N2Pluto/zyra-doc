ยิง load test บน prod clone

สร้าง environment ชั่วคราวที่สเปกเครื่องเท่า prod ทุกตัว แต่แยกออกจาก prod ทั้งหมด เพื่อวัดว่าระบบรับคนได้จริงเท่าไร โดยไม่กระทบลูกค้า แล้วลบทิ้งเมื่อยิงเสร็จ

วันที่ 6 ต.ค. 2026 สถานะ รออนุมัติ ตรวจของจริงแล้ว Phase 0 งบประมาณ ≈ $12 / วันทำงาน

ขออนุมัติ 3 เรื่อง

  1. งบ ประมาณ $1.17 ต่อชั่วโมงที่เปิดใช้ (≈ $12 ต่อวันทำงาน 10 ชั่วโมง) — เปิดเฉพาะวันที่ยิง ยิงเสร็จลบทิ้ง
  2. ข้อมูลใน DB ของ clone จะ restore จากข้อมูลจริงของ prod แล้วลบอีเมล/token ลูกค้าออก หรือใช้ข้อมูลทดสอบอย่างเดียว (Q1)
  3. ขอบเขตรอบแรก รวมระบบเสียง/วิดีโอ (LiveKit) ด้วยเลย หรือเริ่มที่ REST + WebSocket ก่อน (Q4)

ทำไมต้องทำ

ทุกวันนี้เรายังไม่รู้ว่า prod รับคนพร้อมกันได้กี่คน ตัวเลขที่มีอยู่ทั้งหมดเป็นการประมาณ เพราะยังไม่มีที่ไหนยิงขนาดเต็มได้อย่างปลอดภัย

  • ตอนนี้มี 2 node แต่ทุก env ยังใช้ร่วมกันทั้งคู่
    • เครื่องหลัก (e2-standard-4) รัน app, api, ws ของ prod, uat และ dev พร้อมกัน → ยิง REST/WebSocket ที่ dev หนักเมื่อไหร่ prod ช้าตาม เคยเกิดจริงแล้ว 2 ครั้ง (10 ก.ย. และ 22 ก.ย.)
    • เครื่องวิดีโอ (c2d-highcpu-4, แยกออกมาเมื่อ 24 ก.ย.) รัน LiveKit ตัวเดียวที่ทุก env ใช้ร่วมกัน → ยิงห้องประชุม/Spotlight ที่ dev ก็กระทบวิดีโอของ prod
    กฎตอนนี้จึงจำกัดการยิงไว้ไม่เกิน 5 คนจำลอง
  • ยิงจากเครื่องในออฟฟิศไปหา dev ใช้วัดไม่ได้ เวลาเดินทางของเน็ตปนเข้าไปในผล เช่น เข้า office ช้า 1.7 วินาทีตั้งแต่ 5 คน ซึ่งไม่ได้มาจากโหลด
  • การตัดสินใจที่รอตัวเลขนี้อยู่: จะขยายเครื่องไหม, ต้องทำ tick overhaul Phase B/C ไหม (ตั้งเกณฑ์ไว้ที่ 1,000 คน/แผนที่), เปิด Movement V2 เป็นค่าเริ่มต้นได้หรือยัง, ห้องประชุมพร้อมกันได้กี่ห้อง

ข้อเสนอ: clone ที่สเปกเท่า prod แยกทุกชิ้น

หลักการ

  • สเปกเท่า prod: ประเภทเครื่อง, จำนวน replica, CPU/RAM ที่จองไว้, version ของทุก service, ขนาด DB และ Redis คัดลอกจาก prod ตรงๆ
  • ไม่มีอะไรชี้กลับไป prod: DB, Redis, bucket, LiveKit, secret, key ที่ใช้ออก token และระบบ deploy เป็นชุดใหม่ทั้งหมด token ที่ออกให้ clone ใช้กับ prod ไม่ได้
  • มีงานพื้นหลังเท่า prod: ลง monitoring, Argo CD, sfu-lite และ dev/uat จำลองบนเครื่องเดียวกัน เพื่อให้ CPU ว่างเท่าของจริง
  • เครื่องยิงแยกออกมา ไม่แย่ง CPU กับระบบที่ถูกวัด
  • ชั่วคราว: ทุก resource ขึ้นต้นด้วย lt- สร้างก่อนยิง ลบทั้งชุดได้ด้วยคำสั่งเดียว เพราะใช้ Terraform แยกจากของ prod

แผนงาน

Phase 0 · ตรวจของจริง เสร็จ 6 ต.ค.

อ่านค่าเครื่อง, DB, Redis, โหลด 7 วัน และราคา จาก GCP และ cluster จริง ไม่ได้แก้อะไร

Phase 1 · สร้าง infra รออนุมัติงบ

Terraform ชุดใหม่ (state แยกจาก prod): network, เครื่องหลัก, เครื่องวิดีโอ, AlloyDB, Redis, bucket, เครื่องยิง

Phase 2 · Secret + DNS

secret ชุดใหม่ (ปิดอีเมล, ปิด weather provider, ปิด Discord/Sentry ของ prod) และชื่อโดเมน *.lt.zyra.center

Phase 3 · Deploy

Argo CD ของ clone เอง คัดลอก config จาก prod · build หน้าเว็บใหม่จาก commit เดียวกับ prod (URL ถูกฝังตอน build) · ลง monitoring

Phase 4 · ข้อมูล

restore จาก backup ของ prod แล้วล้างข้อมูลส่วนตัว หรือ schema + ข้อมูลทดสอบ ตาม Q1 · สร้างผู้ใช้ทดสอบ lt_ 1,000 คน

Phase 5 · ตรวจก่อนยิง

สคริปต์เช็กว่าทุก URL/IP เป็นของ clone ไม่มีค่าใดชี้ไป prod แล้วรัน smoke 1 คน

Phase 6 · ยิง + สรุป + ลบ

รัน scenario จากเบาไปหนัก เก็บผลพร้อมกราฟ CPU/RAM ช่วงเดียวกัน สรุปเป็นตาราง แล้วลบ clone ทั้งชุดและเช็ก billing ว่าไม่มีอะไรค้าง

เรื่องที่ต้องตัดสิน

Q1ข้อมูลใน DB ของ clonerestore แบบ point-in-time จาก backup ของ prod (มีย้อนหลัง 14 วัน) แล้วล้างอีเมล/token → สมจริงที่สุด แต่มีข้อมูลลูกค้าอยู่ใน env ชั่วคราว ต้องให้ผู้ดูแลข้อมูลอนุญาต · หรือ schema + ข้อมูลทดสอบ → ปลอดภัย แต่ผลเรื่อง DB ดีเกินจริง
Q2ใช้ GCP project เดิมหรือ project ใหม่แนะนำ project เดิม แยก network และสิทธิ์ · project ใหม่แยกขาดกว่าแต่ต้องตั้ง network ไป AlloyDB, registry และสิทธิ์ใหม่ทั้งหมด
Q3จำลองงานพื้นหลังบนเครื่องไหมแนะนำ จำลอง (sfu-lite, monitoring, Argo CD, dev/uat) ส่วนนี้กิน CPU ราว 1.7 core ตอนพีค ถ้าไม่มีผลจะดีเกินจริงเกือบครึ่งเครื่อง
Q4รวมระบบวิดีโอในรอบแรกไหมครบชุด ≈ $1.17/ชม. · เริ่มที่ REST + WebSocket ≈ $0.98/ชม. แล้วค่อยเพิ่มเครื่องวิดีโอ
Q5เครื่องยิงเครื่องเดียวพอไหมเริ่มที่ e2-standard-8 ดูผลรอบแรกของ lt04 ถ้าเครื่องยิงเต็มก่อนค่อยเพิ่ม
Q6วิธี build หน้าเว็บของ cloneเพิ่ม environment loadtest ใน CI ของ zyra-app (ทำซ้ำได้) หรือ build มือครั้งเดียว
Q7เปิด clone นานแค่ไหนแนะนำ เปิดเฉพาะวันที่ยิง ≈ $12/วัน · เปิดค้างทั้งสัปดาห์ ≈ $197
Q8ยิงนอกเวลางานไหมclone ไม่กระทบ prod โดยตรง แต่ถ้าใช้ project เดิมจะแชร์ registry และ Cloudflare ร่วมกัน · ยิงในเวลางานได้ถ้าเลือก Q2 แบบแยก network

เรื่องที่เจอเพิ่มระหว่างตรวจ

ไม่เกี่ยวกับ clone โดยตรง แต่ควรรู้ และควรตัดสินแยก

  • dev ใช้ Redis ตัวเดียวกับ prod และ db เดียวกัน ข้อมูลตำแหน่ง/สถานะใน virtual office ของ dev กับ prod ปนกันอยู่ (uat แยกไปใช้ db อื่นแล้ว)
  • uat ใช้ bucket เดียวกับ prod ไฟล์ที่อัปโหลดตอนทดสอบบน uat ไปอยู่ในที่เก็บของ prod
  • config ของ prod ในเครื่องทีมบางเครื่องตามหลังของจริง ตอน clone ต้องคัดลอกจาก branch main ล่าสุด
  • ช่วงพีคใน 7 วันมี load สูงถึง 15 และหน่วยความจำ 13.4 GiB ยังไม่รู้ว่าเกิดจากอะไร ควรหาสาเหตุก่อนยิง เพราะถ้าเป็นงานประจำ clone ต้องมีด้วย
